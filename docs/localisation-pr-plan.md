## 1. 目标 PR 的范围和拆分

### 1.1 建议的可评审拆分

建议按依赖顺序拆成下列逻辑批次；每批都应能单独构建、测试和回滚。是否最终合并为一个 PR，由官方维护者决定，计划不预先替其批准。

| 批次 | 内容和文件边界 | 依赖 | 合并门槛 |
|---|---|---|---|
| A：框架与显示边界 | `src/Modules/Localisation*`、语言注册表、显示/测宽/光标入口、必要的类接入和英文资源 | 先从 `upstream/dev` 干净重放；不包含未接入框架的技能资源 | 英文行为对照、五种首发语言回退/切换、内部身份与显示字段分离通过 |
| B：稳定资源和简繁基础包 | `src/Locales/en`、`zh-CN`、`zh-TW` 中与 A 已接入路径直接对应的资源和 `Files.lua` | A 的 key/字段契约稳定 | CSV/参数/颜色码/缺字形检查；未覆盖项明确回退，不以资源行数宣称完成 |
| C：技能名称/描述修复 | 当前未提交技能修复及其测试和来源/术语表 | A 已合入且显示控件能读取显式技能字段；不能把依赖未合入的技能修复当独立可用补丁 | 技能槽显示、编辑原文、提示框、搜索、保存身份和首发语言回归通过 |
| D：后续数据域 | 装备、天赋、词缀、风味和其他补译按域单独提出 | A/B 的稳定 key、输入边界和术语决策 | 每域有来源、未决术语、真实路径回归；未覆盖域保持开放 |
| E：工具、CI、文档 | 可长期使用的审计/生成脚本、CI 调用、贡献说明和 PR 资料 | A/B/C 的命令和产物契约确定 | 干净环境可复现，CI 不依赖个人缓存或 Windows 图集 |

最小修改方向是先收敛 A，再以 B、C 为可审阅增量；D 不应和框架首批强耦合。若官方要求一个 PR，仍应在同一分支内按上述边界组织提交和说明，保持每批可单独审查。

### 1.2 必须先分类的文件

- **运行时必要文件**：`src/Modules/Localisation*`、显示类接入、`src/Locales/Manifest.lua`、各语言 `Files.lua` 和被实际加载的资源。它们随对应批次进入 PR。
- **生成文件**：英文/简繁大体量 `Game.csv`、`DataBindings.json`、`MessageBindings.json`、`Locales/Keys/*` 等。应确认生成脚本、输入版本和生成命令后成对提交；不能只提交生成结果，也不能把自动生成文件当手工维护源。
- **长期工具**：`tools/audit-*.py/.lua`、`tools/check-*.py/.lua`、字体构建和资源校验工具。应迁到稳定的 `tools/` 或 `src/Tests` 入口，写清输入、输出、退出码和版本要求。
- **一次性审计产物**：`src/Tests/Run/` 下的候选 JSON/CSV、抓取 HTML、快照、临时脚本和本机 `Settings.xml`，以及过大的逐行报告。先建立清单并让维护者决定保留位置：可复现的最小 fixture/摘要进入 `src/Tests/Fixtures` 或 `docs`，个人/临时材料迁出 PR；本计划不直接删除。
- **二进制/截图**：字体图集、`FontAtlas.exe`、`LuaRunner.exe` 和截图分别按交付需要处理。被 Git 忽略的字体图集不能默认为 PR 资产，截图只能作人工验收证据。

## 2. 合并阻塞项、建议项与范围外

### 合并阻塞项（P0/P1）

1. **基线和可复现性**：必须在干净检出、无本机缓存条件下重建并运行最小测试；不能用当前机器已有 `Fonts`、`Tests/Run` 或 `runtime` 产物掩盖缺文件。
2. **框架/资源依赖闭合**：C 批次技能修复只有在 A 的显式技能显示字段和资源加载路径已合入后才可评审；否则技能测试无法证明独立可用。
3. **英文兼容和身份隔离**：显示名、输入文本、保存名称、内部 ID、哈希、数值和计算对象必须分别验证；不得把译文写回业务身份。
4. **字体交付边界**：确定干净启动所需的 `Glyphs.lua`/TGA 是否由构建生成、是否需要发布包携带，以及 Linux/macOS 是否仅使用英文回退。没有此决定不得宣称跨平台支持。
5. **CI 证据**：上游 `.github/workflows/test.yml` 当前只运行 `spec/System/*_spec.lua` 和 ModCache 检查，不调用 `src/Tests/Localisation*`；必须提出不强制 Windows 图集的接入方式并取得维护者接受。
6. **默认语言决定**：已确认官方场景的新安装默认语言为 English；必须统一 `Manifest.default`、`Main.lua` 缺省读取、初始化和文档示例，并保留旧设置中的显式语言。
7. **来源和术语证据**：每批新增翻译都要标明版本、获取日期、公开位置、匹配/补译方式和待确认项；来源记录不等于许可确认，也不等于翻译质量证明。
8. **真实窗口验收**：headless Lua 测试不能替代真实窗口的字体、布局、DPI、输入法、切换和保存重开证据。至少要有首发语言代表构筑验收记录；未覆盖风味文本等长尾必须显式回退。

### 建议项（P2）

- 将长期审计入口加入统一命令并输出机器可读摘要，保留完整报告作为可选附件。
- 为英文更新建立稳定 key 失效检测：缺 key、参数集合变化、颜色码/换行破坏、字体缺字形和资源文件清单变化都应有非零退出码。
- 将代表构筑和物品/技能 fixture 固定在仓库，避免每次依赖在线 poe.ninja 或个人目录。
- PR 描述提供简洁英文设计说明、可复制命令、构筑样例、前后截图和已知边界；不把历史审计叙述写成当前已验证事实。

### 范围外

- 本计划不恢复 PoeCharm、DLL 注入、每日迷宫或其他旧启动器功能。
- 不重写官方计算逻辑、SimpleGraphic 或 Git 历史；不在计划阶段提交、推送、创建 fork/PR。
- 不承诺首次 PR 穷尽所有风味文本、网络角色 API、账号鉴权、Linux/macOS 中文字体生成和输入法组合状态。
- 不因“没有英文残留”“资源覆盖率高”或断言数量足够而宣称翻译质量、全量覆盖或官方术语已获确认。

## 3. 按依赖顺序的执行清单

每一步都必须记录动作、文件、证据和停止条件；遇到未决产品取舍时停在该步，不用猜测推进。

### P0：重新建立基线和工作树快照

- **动作**：在不改写现有工作树的前提下记录 `git status --short`、`git diff --stat`、`git diff --check`、`git rev-parse HEAD/upstream/dev` 和 305 文件差异清单；从干净临时检出重放 `HEAD` 或拆分候选提交。
- **验证**：临时检出不含 `Fonts`、`tools/*.exe`、`src/Tests/Run` 缓存和个人 `Settings.xml`；记录哪些文件由构建生成、哪些被 `.gitignore` 排除。
- **停止条件**：发现现有未提交技能改动会被覆盖、基线不一致或生成文件无法追溯来源时，先恢复清单和依赖关系。

### P1：框架显示与输入边界审计

- **动作**：逐项核对 `Localisation.lua`、`Dictionary.lua`、`Messages.lua`、`Languages.lua`、`Manifest.lua`、显示类和 `Import.lua` 的职责；把显示、测宽、光标、搜索、输入反向转换和保存身份写成接口清单。
- **当前证据**：`Font.New` 直接 `dofile(folder .. '/Glyphs.lua')`；`activeFont` 在测宽、绘制和光标入口被调用；`Manifest` 的中文、日文和韩文语言均有独立字体配置；技能修复文档和代码已区分 `inactiveText` 显示名与编辑缓冲区。
- **验证**：英文模式与 `upstream/dev` 输出/数值对照；首发语言切换后缓存清理；英文/中文搜索、物品/角色导入、保存重开保持原 ID、名称和数值。
- **停止条件**：任何调用点仍用最终绘制英文反查决定业务身份，或测试只证明字符串变化而未证明真实字段边界时，不进入资源大批量迁移。

### P2：字体、构建和正式资源交付调查

- **动作**：在无既有缓存的 Windows 机器上执行 `build.cmd`，核对 VS/MSVC、Noto Sans CJK、`FontAtlas.cpp`、`LuaRunner.cpp` 的前置条件；分别测试英文回退（无图集）、简繁日韩字体、坏/缺 `Glyphs.lua` 和正式打包目录。
- **必须回答的问题**：`src/Locales/Fonts/` 被 Git 忽略时，干净启动是按语言懒生成、发布包携带还是明确要求用户先生成？CI 是否只跑英文/headless，Windows 图集是否成为可选 job？字体缺字形、TGA 损坏和图集路径错误的错误信息是什么？支持平台边界是什么？
- **验证**：记录干净启动/CI/打包三套结果和日志；`python tools/check-atlas.py` 只作为图集格式证据，不能替代窗口验收。
- **停止条件**：无法在干净环境重现、字体覆盖不足、懒生成器未随正式包提供，或正式包与源码启动依赖不同且没有维护者决定时，不把字体工具写成必需的跨平台能力。

### P3：默认语言和兼容策略决策

- **动作**：检查旧 `Settings.xml` 无 `Misc.language`、非法语言、显式五种首发语言、切换后保存重开，以及旧构筑/导入/计算结果。
- **决定**：官方场景的新安装默认语言为 English；旧 `Settings.xml` 中显式保存的语言继续生效，新增日文和韩文使用同一回退链。
- **验证**：无语言字段、非法语言和五种显式语言都能正确回退/持久化；显示语言变化不改写原始构筑、导入数据、计算值或导出格式。
- **停止条件**：发现旧设置的显式语言被覆盖，或默认切换改变业务数据/计算结果时，回到兼容策略步骤。

### P4：资源来源、术语和长期维护流程

- **动作**：对 `localisation-skill-sources.csv`、`localisation-skill-terminology.csv`、装备来源表及简繁资源建立字段契约：稳定 key、英文版本/hash、来源 URL、获取日期、匹配方式、手工补译、术语复用、待确认状态、许可状态。
- **维护规则**：优先复用仓库已有译名；无可靠对应时保留英文并列入待确认；不以音译替代未知官方术语。数字、命名参数、颜色码、换行、单位和字形必须有结构检查。英文数据/key 更新时，工具应报告失效映射、缺资源和参数差异。
- **验证**：从公开来源重新生成一小组样本；审计脚本在无网络时能使用固定 fixture；来源和许可分别记录，不能把“可定位”写成“可再分发已获授权”。
- **停止条件**：发现来源不可复核、译名冲突或许可未确认时，保留原文/待确认清单，不批量替换资源。

### P5：上游 CI 和 ModCache 计划

- **动作**：在现有 `.github/workflows/test.yml` 基础上规划四类 job：官方系统测试、headless 本地化契约/回归、干净资源/脚本检查、ModCache 生成差异检查。把 Windows 图集构建放在可选或单独的 Windows job，避免所有 Linux 测试都依赖 `FontAtlas.exe`。
- **验证**：在与上游容器相同的 Linux 环境运行 Lua 契约；在 Windows job 验证字体/真实窗口所需命令；明确 `src/Tests/Localisation*` 的入口、超时、fixture 和失败日志上传方式。
- **停止条件**：无法给出无图集的英文/headless 路径，或 CI 会因个人字体、网络、在线构筑和本机缓存而不稳定时，不把该方案提交给维护者。

### P6：真实窗口验收矩阵

- **动作**：准备 English/简体/繁体/日文/韩文五套环境和代表构筑，覆盖技能、装备、天赋、配置、比较、导入和设置页；测试长提示换行、颜色码、DPI/缩放、搜索、中文输入法、编辑/粘贴、语言切换、保存重开。
- **证据分层**：headless Lua 只证明调用路径、字段/数据边界和异常；真实窗口截图/录屏/人工记录证明视觉布局、字体、裁剪、输入法和交互。两类证据分别归档，不能互相替代。
- **验证**：每个场景记录语言、构筑/fixture、窗口尺寸/DPI、步骤、预期、实际、截图路径和结果；未覆盖风味文本、网络链路等列为回退或范围外。
- **停止条件**：出现布局溢出、中文输入破坏原文、切换后缓存旧译文、保存后身份改变或任何 Lua 错误时，回到相应 P1/P3 修复计划，不以“未覆盖场景”关闭。

### P7：PR 整理和维护者评审材料

- **动作**：核对 `CONTRIBUTING.md` 的 `dev` 目标、系统测试、ModCache 规则和 PR 模板；整理英文 PR 说明、设计边界、可复现步骤、构筑样例、截图和已知限制。
- **文档清理范围**：移除个人机器路径、过时的“未创建 fork”等历史陈述；把旧基线审计、当前结论和待验证项分段。历史报告只做修订/迁出提案，不在本计划阶段删除或改写。
- **验证**：维护者可仅按 PR 说明在干净检出重现最小路径；文件清单、生成命令、测试命令和截图相互对应；所有未决决定显式列出负责人和阻塞关系。
- **停止条件**：贡献指南、PR 模板、CI 方案或默认语言仍有冲突时，先提交决策问题，不进入对外 PR 操作。

## 5. 完成条件

只有同时满足以下条件，才可把计划标记为“具备提交条件”；它不等于 PR 已提交或已合并：

1. 已按 `upstream/dev` 当前提交重新生成干净差异和文件分类，且所有现有未提交技能改动均被保留并有归属。
2. A/B/C 的依赖闭合，生成源与生成文件成对可追溯；一次性审计产物去留得到维护者决定。
3. 字体干净构建、英文回退、正式打包和平台边界有直接日志；没有把静态检查写成启动/CI 已失败或已通过。
4. 默认语言、旧设置兼容、显示/输入/保存身份分离和 CI job 设计均有明确决定与验收证据。
5. 简繁资源有来源、术语复用和待确认清单；参数、数字、颜色码、换行和字形检查可重复，许可状态单独记录。
6. 首发语言真实窗口验收与 headless 证据分开归档，代表构筑和已知回退范围可复现。
7. PR 说明、贡献指南、生成命令、测试命令、截图和限制相互一致；工作树完成前最后一次验证使用最新命令和退出码。

在这些条件满足前，最安全的结论是“已形成可评审执行计划，仍有合并阻塞项和维护者决策”，而不是“汉化已完成”或“PR 可直接提交”。
