# K4：移除旧显示反查及新增文本检查

最后组合补译与最终验收已完成：311 个分类入口、216／423,612 项回归通过；本报告下方为 K4 首轮证据，当前状态见 [最终交付记录](localisation-delivery-2026-10-31.md)。

用户明确要求继续 K4，以免后续新增文字继续依赖英文原文碰撞。此批已移除全局显示兼容依赖，补齐移除后暴露的已验证显示绑定，并接入防回退检查。本报告是当前状态；其他批次报告的计数及“未完成”描述保留对应历史时点。

## 根因与改动

旧 `localisation:Translate` 在绘制、测宽、提示框和通用搜索中按最终英文字符串查词典。它掩盖了漏绑资源的调用点，也无法区分相同英文的业务用途与用户名称。通过移除反查前后的真实绘制对照，确认默认名称、热力图、警告数量、自动技能组、投射物状态和计算来源仍在依赖此路径。

- 删除 `localisation:Translate` / `Match`、显示缓存及切换语言时的旧词典加载；字体、换行和光标仍负责文本布局。
- `Tooltip:AddLine` 接收已解析文字；编辑框的标题与占位符通过独立资源属性解析，用户缓冲区保持原文。
- 对照暴露的调用点补显式 key、列表引用和限定业务字段的枚举；新增英文、简体、繁体各 30 个 key。
- 自动默认名称保留独立显示引用；用户填写或导入时明确保存的名称原样保留。导出选择器的自定义标题不再被默认 key 覆盖。
- 公共 `string:matchOrPattern` 只匹配原文；游戏对象检索用 `MatchField` / `MatchModLine`。旧 `Dictionary` 仅用于输入转换及独立审计。

## 后续新增检查

首次安装工具依赖运行 `npm ci --prefix tools`。`test-localisation.cmd` 先运行 `tools/check-localisation-display.cjs`，再执行契约及实际应用集成测试。

检查执行显示、字段、列表、状态、显示状态、计算报告六种 AST 扫描，对照 `localisation-display-review.json` 中 306 个已分类入口。新增或改变的候选必须绑定稳定 key，或逐项追溯来源并说明保留原因；固定资源引用须存在。不得整体重建清单来接受新候选。

四个反例均返回失败：新增未绑定字面文字、新增共享变量显示入口、恢复旧 Translate 调用、引用不存在的固定 key。探针执行后源码原始字节已恢复。此检查覆盖已实现扫描形式，不保证发现任意间接赋值或反射生成的文案。
