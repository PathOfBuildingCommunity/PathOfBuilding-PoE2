# 天赋树拖动与绘制性能排查

日期：2026-10-31。

## 问题与根因

实际窗口中执行从 (800, 377) 到 (1000, 527) 的快速拖动，按下与释放回调相隔 16 毫秒，旧代码下画面没有平移。

Main 的输入队列原本只保存按键类型。PassiveTreeView 到绘制时才读取当前位置作为拖动起点；释放时又先依据实时按键状态清空拖动信息。同一帧内完成的拖动，以及释放帧最后一段位移，都会因此丢失，还可能被误当成节点点击。滚轮中心也使用绘制时的位置，光标移动后会偏离事件发生点。

绘制层面的额外开销来自完全位于屏幕外的天赋树图片仍然提交 DrawImage。连接线已有可见区域判断，DrawAsset 没有对应判断。

## 修改范围

- Main 的按下和释放事件保存当时的光标坐标。
- PassiveTreeView 在清理释放状态前先补齐位移，按相同的 5 像素阈值区分拖动与点击。实时按键状态仍用于失焦后解除拖动。
- 滚轮缩放围绕事件坐标；没有坐标的旧调用仍回退当前光标。
- DrawAsset 按实际图片边界跳过完全屏幕外的绘制，保留边缘重叠图片，半幅背景按上下拼接后的范围判断。

## 性能对照

在同一原生应用窗口、同一构筑与视图中，预热 30 帧，再分别采样 120 帧。保持输入与节点逻辑相同，仅切换 DrawAsset 的屏幕外裁剪。使用 GetTime 测量主循环中的 Lua 处理耗时，使用 LuaJIT 采样分析辅助定位。

| 指标 | 原绘制路径 | 加入屏幕外裁剪 |
| --- | ---: | ---: |
| 帧内处理耗时中位数 | 10 ms | 8 ms |
| P95 | 10 ms | 9 ms |
| 最大值 | 11 ms | 10 ms |
| 平均帧间隔 | 16.667 ms | 16.667 ms |

当前视图的处理耗时中位数减少约 20%；两组帧间隔都保持约 60 FPS，因此这里说明的是处理余量改善。该数据不能代表所有构筑、缩放级别或首次加载耗时。

## 用户操作复测：提示翻译导致主线程停顿

用户反馈首轮修复后仍卡顿。按用户要求临时安装应用内探针，并用独立的 Windows 只读鼠标监听器记录目标窗口输入；由用户亲自拖动，未注入鼠标操作。系统记录与应用记录采用相同 QPC 时基，只采集鼠标按钮、位置和滚轮，不采集键盘文本。

本轮有效采样约 18.309 秒，共 394 帧；系统与应用均记录到 38 次左键按下、39 次松开。存在连续按下、额外松开，按连续完整按下／松开配成 34 组；其中 23 组在应用回调中读到了相同坐标。该数值是坐标重合计数，不将所有组都视为满足视口条件的独立拖拽。

- 帧内耗时中位数 11.192ms，17 帧超过 100ms，最慢 1653.991ms。
- 节点提示生成的 16 次计时累计约 7013ms；字体测宽等后续绘制也会重复进入翻译。
- 采样期间天赋树最终相对初始位置平移约 (+263, -761) 个虚拟屏幕像素；缩放等级一直为 15，本轮没有滚轮事件。

可直接复核的第 8 组：系统在 QPC 240630.1475795 秒按下于客户区 (678,499)，在 240630.3490642 秒松开于 (1155,512)，实际移动 (+477,+13) 像素，持续约 201ms。应用在约 294ms 后才处理按下，按下和松开都读取到 (825,580)。第 153 帧耗时 375.912ms；第 154 帧收到这一对事件，日志中的树位置前后完全相同，实际平移 (0,0)。

因此首轮在回调里保存 GetCursorPos 的改动，只保住了回调到绘制之间的位移；主线程在回调之前被同步工作阻塞时，历史鼠标位置仍然无法由当前位置恢复。此次继续定位造成阻塞的同步工作。

### 根因与修复

独立进程重放采样中涉及的 5 个节点提示，LuaJIT 栈采样集中在 Dictionary:Translate 的模板遍历。简体词库有 37522 个模板，其中 16136 个没有固定前缀。每个新文本、递归片段和测宽文本都可能逐条尝试数万次模式匹配。首次分解测量中，翻译累计约 1810ms，属性计算约 35ms。

修复仅在 Dictionary.lua 为模板建立较长固定前缀或后缀的索引，按实际文本取候选，随后仍按原先的模板优先级执行原模式匹配。反向歧义、占位符重排、重复占位符、词条覆盖和未知输入回退继续使用原逻辑。没有增加悬停延迟。
